# Meaning — Semantic Search Engine

Search a small FAQ set by *meaning*, not keywords, using sentence embeddings
and cosine similarity. Includes a side-by-side "semantic vs keyword" view so
the value of embeddings is visible, not just claimed.

- **Backend:** FastAPI + `sentence-transformers` (local, free embedding model — no API key needed)
- **Frontend:** React (Vite)

---

## 1. Run the backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

First run will download the embedding model (`all-MiniLM-L6-v2`, ~80MB) —
this needs internet access once, then works fully offline. The API will be
running at **http://localhost:8000**. Visit **http://localhost:8000/docs**
for interactive API docs (auto-generated by FastAPI).

## 2. Run the frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

This will be running at **http://localhost:5173**. Open it in your browser
and search.

## 3. Try it

Search something that shares almost no words with the answer, e.g.:

- "how do I get my money back" → should surface the refund policy FAQ
- "I forgot my login credentials" → should surface the password reset FAQ

Compare the semantic column (blue) against the keyword column (amber) —
keyword search will often come up empty or find the wrong FAQ, while
semantic search finds the right one by understanding meaning.

---

## How it works

1. Every FAQ in `backend/data.json` is converted into a vector (embedding)
   using a pretrained sentence embedding model, once, at startup.
2. When you search, your query is converted into a vector the same way.
3. The query vector is compared against every FAQ vector using **cosine
   similarity** — how close their directions are in vector space.
4. The FAQs with the highest similarity scores are returned, ranked.

No fine-tuning, no training — this uses a pretrained model purely for
inference, and everything runs locally for free.

## Customizing

- **Swap in your own data:** edit `backend/data.json` — any list of
  `{id, question, answer}` objects works.
- **Change the embedding model:** edit the model name in `backend/search.py`
  (e.g. try `all-mpnet-base-v2` for higher quality but slower embeddings).
- **Deploy:** backend to Render/Railway (free tier), frontend to Vercel
  (free tier). Set `VITE_API_URL` in the frontend's environment variables
  to point at your deployed backend URL.
